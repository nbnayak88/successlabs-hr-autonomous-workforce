# Knowledge Assets Lab — General Handbook

**Lab:** Knowledge Keystone Lab (KAL)  
**Track:** 16 — Resources  
**Learning Intent:** **DOCUMENT**  
**Maturity Stage:** Intermediate  
**Core Intention:** Structure and preserve knowledge into reusable organizational assets.  
**Student Outcome:** Build reusable intellectual property.

> **Wisdom that isn't captured is wisdom that disappears.** KAL develops the discipline to convert experience, insight and learning into structured knowledge assets that remain useful beyond a single project or person.

---

# 1. Purpose

KAL is the **knowledge preservation and reuse layer** of the 20-Lab ecosystem.

It helps professionals move from:

**Experience → Capture → Structure → Connect → Find → Reuse → Maintain**

The objective is not simply to write documents. It is to create **reliable organizational knowledge assets** that another person can discover, understand and apply.

The KAL loop is:

**CAPTURE → STRUCTURE → CONNECT → PUBLISH → FIND → APPLY → REVIEW → UPDATE → PRESERVE**

---

# 2. KAL Philosophy

1. **Document is your intent** — structure and preserve knowledge into reusable assets.
2. **Capture while it's fresh** — document insights before memory fades.
3. **Structure for reuse** — make assets actionable for someone other than the creator.
4. **Make it findable** — knowledge that cannot be located is effectively lost.
5. **Think in mindmaps and systems** — connect knowledge so relationships become visible.
6. **Operate at the Intermediate level** — turn experience into reusable intellectual property.
7. **Document across the 11 GICS sectors** — preserve sector-specific context.
8. **Preservation serves the mission** — documented knowledge gives future practitioners a head start.

# 13. Knowledge Troubleshooting

### Nobody can find the document
Improve taxonomy, naming, metadata and authoritative-location discipline.

### People keep asking the same question
Create or improve the corresponding knowledge asset.

### Documentation is too long
Separate reference detail from the minimum actionable path.

### Different documents contradict each other
Establish a source of truth and reconcile versions.

### Asset is technically correct but unusable
Rewrite around user tasks and decisions.

### Documentation becomes stale
Assign ownership and establish review triggers.

### Knowledge exists only in one person's head
Capture the expert workflow through interviews, walkthroughs and examples.

### Multiple teams recreate the same guidance
Consolidate common knowledge and preserve context-specific variations separately.

### AI/search returns poor answers
Improve structure, metadata, terminology, relationships and authoritative-source quality.

# 14. Knowledge Lifecycle

Use:

**Create → Review → Approve → Publish → Use → Measure → Update → Archive**

Every important asset should have a lifecycle state such as:

- Draft
- Review
- Approved
- Published
- Deprecated
- Archived

Never allow outdated material to appear indistinguishable from authoritative guidance.

# 21. KAL Rule Book — Operationalized

### Do
- Capture insights while they are fresh.
- Structure knowledge for reuse.
- Make assets easy to find.
- Use clear naming and taxonomy.
- Connect related knowledge.
- Use mindmaps where relationships matter.
- Build playbooks others can follow.
- Capture sector-specific nuances.
- Assign ownership.
- Keep assets current.
- Write clearly and simply.
- Treat documentation as organizational intellectual property.

### Don't
- Rely on memory.
- Create documents nobody can apply.
- Bury knowledge in personal drives or disconnected locations.
- Create duplicate conflicting sources of truth.
- Let documentation become stale.
- Document only for yourself.
- Hide important assumptions.
- Publish restricted knowledge without appropriate controls.
- Confuse volume of documents with knowledge maturity.
- Treat documentation as a clerical chore.
